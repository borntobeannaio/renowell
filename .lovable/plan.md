## Что происходит

Кнопка «Создать» в форме добавления сотрудника отправляет запрос через Yandex Cloud proxy на edge-функцию `create-employee-user`. Функция возвращает `401 Invalid token` (проверено через `curl_edge_functions`). Это означает, что вызов `supabase.auth.getUser(access_token)` внутри функции не может валидировать текущую сессию пользователя.

Причина: в проекте включена новая система асимметричных ключей подписи (в секретах присутствует `SUPABASE_JWKS`). После её включения `supabase.auth.getUser(token)`, инициализированный с `SUPABASE_ANON_KEY`, начинает падать для токенов, выпущенных новой парой ключей. Официально рекомендованный метод — `supabase.auth.getClaims(token)`, который валидирует JWT по JWKS локально.

Ошибка в UI («invalid token») — это та самая строка, которую функция возвращает в ответе.

## Что меняем

1. `supabase/functions/create-employee-user/index.ts`
   - Заменить `supabase.auth.getUser(token)` на `supabase.auth.getClaims(token)`.
   - HR-админа определять по `claims.email` (fallback `claims.user_metadata.email`).
   - Сохранить приём токена и из `Authorization`, и из `body._accessToken` (нужно для Yandex proxy).
   - Логировать причину невалидности токена в консоль функции, чтобы такие случаи было проще диагностировать в будущем.

2. `supabase/functions/delete-employee/index.ts`
   - Ровно та же замена (`getUser` → `getClaims`) — иначе удаление сотрудника отвалится по той же причине.
   - Добавить поддержку `body._accessToken`, чтобы вызов через Yandex proxy работал единообразно с созданием.

3. Никаких изменений в клиенте, в схеме БД, в правах и в списке HR-админов не делаем — доступы у `sonya369@gmail.com`, `anna.rum91@gmail.com`, `astashkina495@gmail.com`, `oparin@renowell.ru` уже настроены корректно.

## Проверка после деплоя

- Тестовым curl на `/create-employee-user` с заведомо неверным токеном должен вернуться `401 Invalid token` (валидация работает).
- Реальный вызов из формы под аккаунтом HR-админа — сотрудник создаётся, показывается пароль.
- Тем же путём проверить удаление сотрудника.

Если пользователь всё ещё видит `Invalid token` после фикса — значит его вкладка держит токен, выпущенный до ротации ключей; решение — выйти и войти снова, чтобы получить свежий JWT.
