## 1. Заметки — отдельный пункт меню «Заметки»

В сайдбаре/нижней навигации добавляется новый пункт **«Заметки»** (отдельная страница `/notes`), а не секция в профиле.

**Страница «Заметки»:**
- Две вкладки: **Личные** / **Рабочие**.
- Личные — видит только владелец.
- Рабочие — видят все сотрудники; также подтягиваются на карточку сотрудника в HR (вкладка «Рабочие заметки»).
- Создание, редактирование, удаление, поиск, закрепление, сортировка по дате.
- Автосохранение черновика (3 сек, по аналогии с протоколами).

**Технически:**
- Таблица `employee_notes`: `id`, `owner_profile_id`, `visibility` (`private`|`work`), `title`, `body`, `pinned`, `created_at`, `updated_at`.
- RLS: SELECT `private` — только владелец; SELECT `work` — все authenticated; INSERT/UPDATE/DELETE — только владелец.
- Маршрут `/notes` → `NotesPage` с двумя вкладками.
- Пункт меню «Заметки» добавляется в сайдбар и в нижнюю мобильную навигацию (видим всем по правилу «menu items always visible»).
- Хук `useEmployeeNotes(ownerId?, visibility?)` на `proxySelect/Insert/Update/Delete`.
- На карточке сотрудника в HR — отдельная вкладка «Рабочие заметки» (read-only для чужих, владелец редактирует свои).

## 2. Строительные протоколы — третья вкладка «Строители»

В существующем модуле `ProtocolsModule` добавляется третья вкладка **«Строители»** рядом с «Протоколы совещаний» и «Тендер-протоколы». Структура и UX — точно как у обычных протоколов (секции по проектам, пункты, ответственные, синхронизация с задачами, PDF-экспорт, комментарии к пунктам).

- Плюс администраторы протоколов: `sonya369@gmail.com`, `anna.rum91@gmail.com`

*(Подтвердите email 4 РП перед запуском, чтобы прописать их в коде. Если потом нужно расширить список — это правка одной строки.)*

**Доступ к конкретному стройпротоколу:**
- При создании РП в поле **«Участники протокола»** отмечает сотрудников (multi-select).
- Автор + отмеченные участники + `sonya369@gmail.com` / `anna.rum91@gmail.com` → видят протокол и могут редактировать (пункты, ответственные, PDF).
- Все остальные сотрудники этот протокол **не видят**.

**Технически:**
- Используем существующую таблицу `protocols`, новый `meeting_type = 'construction'`.
- Добавляем колонку `participant_ids uuid[] default '{}'` в `protocols` (profile.id участников). Автор добавляется автоматически.
- Расширяем `useProtocolPermissions`:
  - `CONSTRUCTION_AUTHORS` — список email 4 РП.
  - `CONSTRUCTION_ADMINS = ['sonya369@gmail.com', 'anna.rum91@gmail.com']` — полный доступ ко всем строй-протоколам.
  - `canCreateConstructionProtocol = email ∈ CONSTRUCTION_AUTHORS ∪ CONSTRUCTION_ADMINS`.
  - `canViewConstructionProtocol(protocol) = profileId ∈ protocol.participant_ids || email ∈ CONSTRUCTION_ADMINS`.
- В `ProtocolsModule`:
  - Третья `TabsTrigger` «Строители» с фильтром `meeting_type === 'construction'`.
  - Список фильтруется на клиенте через `canViewConstructionProtocol` (по аналогии с приватностью календаря/чатов).
  - Кнопка «Новый строй-протокол» → `/protocols/new?type=construction`.
- В редакторе `/protocols/new` и `/protocols/edit/:id` при `type=construction`:
  - Поле **«Участники протокола»** (multi-select сотрудников) рядом с «Организатор/Присутствовали».
  - Заголовок: «Строительный протокол».

## Что НЕ меняем

- Обычные протоколы совещаний и тендер-протоколы — без изменений.
- Действующие списки `PROTOCOL_ALLOWED_EMAILS`, `PROTOCOL_EDITORS`, `PROTOCOL_ADMINS` остаются.
- Профиль `/profile` — без изменений (заметки переехали в отдельный пункт меню).
